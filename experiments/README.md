# 软趴趴大乱斗消融记录

本轮以保留已上线的玩法、角色外观、联机和旧回放为约束。实验前核对了全部 36 个浏览器文件，内容与 [GitHub 首发版本 c6ba55f](https://github.com/Ranko-sama/ruanpapa/tree/c6ba55f2775a4d3fa4d371ae6fd4399228566d2d) 一致。

| 实验 | 观察 | 处理 |
| --- | --- | --- |
| 删除碰撞体缓存的子步位移，在弹道检测时用当前坐标减去子步起点 | 30 场完整对局的 96,236 个物理步，逐步比较的回放帧、事件和结算全部一致 | 采用 |
| 进一步取消对移动目标的弹道补偿 | 云顶经典乱斗，种子 18961，第 2257 步首次与基线分叉（从 0 计数） | 保留补偿 |
| 删除接触求解后的地板校正 | 箱子从 1.35 高度压住角色的回归用例在第一个物理步失败 | 保留校正 |
| 机器人直线追目标，取消绕路 | 船坞护旗机器人追对岸旗帜时掉入水道 | 保留寻路 |
| 合并两套 Canvas 场景绘制 | 直接合并后旧擂台全场视角变慢。共用镜头和场景绘制，俯视圆面交给 Canvas 原生绘制，果冻折射共用一块临时画布，并按屏幕尺寸选择采样条数 | 采用实测较快的组合 |
| 移除判断连接是否过期的额外计数器、手动回执标记和两份独立长码 | 用当前 WebRTC 连接识别过期请求。一次成功的局域网配对从编码两份长码降到零，静态网页仍各编码一份邀请和回执 | 采用 |

## 复验物理

在项目根目录执行。第一个参数指向基线版本中直接含有 `sim.js` 的目录，第二个参数默认指向当前仓库根目录。复验下面的首发版本时可使用 Node.js 24。

```sh
node --test
git worktree add --detach ../ruanpapa-before c6ba55f2775a4d3fa4d371ae6fd4399228566d2d
node experiments/compare-sim.mjs ../ruanpapa-before
```

对照脚本遍历五张地图和六种模式，让两个版本逐步接收同一份输入，直到结算。首次出现差异时会报告地图、模式、种子和步数。本轮用 Node.js 24.19.0 得到的记录摘要为 `07a9f676a98d2db3c71ce306841fe348836a6459961c76506cfd2d89170c71ed`。两项取消地板校正和取消寻路的实验分别可用已有的 `descending crate`、`flag bot` 测试单独验证。

## 绘制与联机

- 在同一台电脑的 Chrome 156 中禁用 WebGL，视口为 800 × 520，像素比为 1。用种子 914 的云顶乱斗生成 64 个固定帧，预热后交替绘制各版本，每批 75 帧并在批末读取一个像素。首轮直接合并后从 1.42 增至 2.05 ms/帧。最终九轮对照的中位数分别为基线 1.41、精简折射但逐段绘制圆面 1.57、使用原生圆面的最终版 **1.31 ms/帧**。这些数值是该场景的绘制耗时。
- WebGL 下五张地图各取三个视角，15 张固定帧截图与基线逐像素一致。Canvas 下验证了完整、预警和破碎玻璃，以及旧小擂台布局。对诊断条纹图，半径 12 × 15 像素的小果冻内，红绿通道相对基线的平均绝对差为 3.66（通道范围 0–255）。半径 46 × 60 和 95 × 120 时分别为 0.11 和 0.09。三个尺寸均保有双轴折射。
- 两个独立浏览器会话分别用六位房间码和邀请回执开局，并验证客机按键抵达房主。新版和旧版轮流担任房主也能配对并传递输入。43 项自动测试全部通过，其中新增的两项覆盖房间服务失败时的手动邀请和取消后迟到的房间响应。
